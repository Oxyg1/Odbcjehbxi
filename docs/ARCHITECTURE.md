# PlsDonate — архитектура MVP

Telegram Mini App: пользователь собирает свой стенд из собственных стикеров и
получает донаты в Stars и TON. Ключевое решение продукта — свободный 2D-конструктор
вместо шаблонов, поэтому вся архитектура строится вокруг одного формата данных:
стенд это список слоёв, а не картинка.

## Стек

| Слой | Решение | Почему так |
| --- | --- | --- |
| Mini App | React 18 + Vite + TypeScript, Telegram WebApp SDK | WebView, минимум зависимостей, быстрый холодный старт по прямой ссылке |
| API | Node + TypeScript + Fastify | нужен приём вебхуков Bot API, WebSocket для тикера и общая схема стенда с фронтом |
| Хранилище | PostgreSQL (Prisma) | стенд лежит в `jsonb`, донаты и инвентарь — обычные таблицы |
| Реалтайм и очереди | Redis (pub/sub + очередь модерации) | тикер донатов и асинхронная проверка загрузок |
| Файлы | S3-совместимое хранилище | оригиналы и превью ассетов |
| Бот | grammY на вебхуках, тот же процесс Fastify | загрузчик ассетов и платёжные апдейты Stars |

Общий код (схема стенда, лимиты, геометрия) живёт в `packages/shared` и
импортируется и фронтом, и API — расхождение валидации между клиентом и сервером
исключено на уровне сборки.

## Формат стенда

```jsonc
{
  "version": 1,
  "background": "#14141B",
  "layers": [
    { "id": "l_...", "assetId": "u_star", "x": 0.5, "y": 0.44,
      "scale": 0.42, "rotation": -7.5, "zIndex": 3 }
  ]
}
```

Поля соответствуют требованию `(asset_id, x, y, rotation, scale, z_index)`;
в TypeScript они названы по правилам языка (`assetId`, `zIndex`).

Координаты нормализованы по холсту:

- `x`, `y` — центр слоя в долях ширины и высоты; JSON не зависит от размера экрана;
- `scale` — ширина слоя в долях ширины холста, высота берётся из пропорций ассета;
- `rotation` — градусы, любой угол;
- `zIndex` — порядок в стопке.

Это даёт три вещи, ради которых формат и выбран: стенд перерисовывается в любом
разрешении (экран доната, карточка для Stories, превью), редактируется без потери
качества и в будущем поддаётся ремиксу — но ремикс в MVP не входит.

### Зависимость: модерация перед свободной загрузкой

Этап 3 не выкатывается частями. Пока в очереди нет автофильтра (NSFW-классификатор
на загруженной картинке до попадания в инвентарь) и очереди ручной проверки для
пограничных случаев, приём файлов от пользователей не открывается — инвентарь
остаётся на фирменных ассетах. Порядок такой: приём файла → превью и хэш → автофильтр →
`approved` в инвентарь, `review` в ручную очередь, `rejected` с ответом пользователю в бот.

## Chrome и Canvas

Интерфейс (Chrome) и стенд (Canvas) не смешиваются:

- всё оформление Chrome задано переменными в `styles/tokens.css`, значения по месту не пишутся;
- акцент `#FFB84D` зарезервирован за кнопкой доната и эффектом успешного доната,
  поэтому в редакторе его нет ни на одном элементе;
- `#4DD9C0` зарезервирован за живыми состояниями (тикер, «в эфире»);
- переходы 150–180 мс без отскоков; единственный громкий момент в продукте — успешный донат;
- платный ассет отличается фактурой фольги, а не яркостью.

Верх и низ холста — защищённые зоны под системную плашку Telegram и кнопку доната.
Слой туда поставить можно; на зону ложится затемняющий scrim, а пока слой в руке —
подпись, что окажется на этом месте. Запрета на позиционирование нет.

## Производительность

Целевое устройство — средний Android в WebView, не топовый iPhone.

- Во время жеста стор не трогается: кадры пишутся прямо в DOM через `requestAnimationFrame`,
  React получает одно обновление на отпускание пальца.
- Масштаб задаётся размером элемента, а не `transform: scale()` — картинка растрируется
  в своём реальном размере, а не в размере холста.
- Бюджет анимации (5 слоёв) виден постоянно; превышение возможно только после явного
  подтверждения с предупреждением о просадке.
- `?perf=1` включает счётчик кадров для проверки сценария с 5–8 анимированными слоями.

## Вне скоупа MVP

Каталог и браузинг чужих стендов, ремикс чужих стендов, кастодиальный TON-кошелёк,
нативные приложения вне Telegram.
