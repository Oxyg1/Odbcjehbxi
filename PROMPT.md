### Этап 1 — Безопасность (сначала, отдельным коммитом)

В `frog_bot.py` лежит живой токен бота и живой Telegram WebApp `initData`
как fallback-значения `os.getenv`. Я их ротирую сам, но код должен быть готов:

- Все секреты — только `os.environ["X"]`, без fallback-значений
- Загрузка `.env` через `python-dotenv`
- `frog_bot.py` **не коммитить в git**, пока в нём есть секреты
- Проверить, что `.gitignore` покрывает `.env`, `*.db`, `*.log`

### Этап 2 — Скелет нового пакета

Создай структуру, но **не переноси в неё логику пока**:

```
frog_bot/
  __main__.py          — точка входа, сборка Application
  config.py            — env, константы, никаких секретов в коде
  core/
    db.py              — ОДИН слой доступа к БД (см. §4)
    ui.py              — UI-kit: кнопки, экраны, разделители (см. §5)
    router.py          — регистрация роутеров с pattern=
    errors.py          — обработка ошибок, логирование
  features/
    __init__.py        — реестр фич: каждая фича = router + команды
  legacy.py            — импорт старого on_callback как fallback
```

Ключевое: в `__main__.py` роутеры регистрируются **до** legacy-fallback:

```python
app.add_handler(CallbackQueryHandler(gacha.router,  pattern=r"^gacha_"))
app.add_handler(CallbackQueryHandler(nft.router,    pattern=r"^nft_"))
# ... перенесённые фичи ...
app.add_handler(CallbackQueryHandler(legacy.on_callback))   # всегда последним
```

Так каждая перенесённая фича начинает работать через новый код, а всё
остальное продолжает жить в старом. Ничего не ломается разом.

## 4. Правила работы с БД — обязательные

Эти правила — прямое следствие найденных гонок в экономике (AUDIT.md §3).

1. **Любое изменение числового поля — атомарным SQL, не Python-ом.**
   ```python
   # ❌ теряет параллельные обновления
   f["coins"] = f.get("coins", 0) - price
   await db_save(f)

   # ✅
   new_balance = await db_coins_delta(uid, -price)
   if new_balance is None:
       return await q.answer("Недостаточно КваКоинов", show_alert=True)
   ```
   Причина: `db_save` пишет обратно **всю строку** (137 колонок), поэтому два
   параллельных обработчика затирают друг другу не только монеты, а уровень,
   XP, инвентарь и кулдауны.

2. **Один слой доступа.** Сейчас 814 прямых `aiosqlite.connect` против
   13 использований написанного пула `_DBPool`. В новом коде — только `core/db.py`.

3. **Не кэшировать изменяемые числовые поля.** `_UserCache` с TTL 60 сек
   раздаёт устаревшие балансы и увеличивает окно гонки до минуты.

4. **Схему не менять** на этом этапе. Работаем с существующими 80 таблицами.

## 5. Правила UI — обязательные

Это лечение «каши». Все правила проверяемы, поэтому не спорь с ними без причины.

1. **Только `btn()` из `core/ui.py`.** Сырой `InlineKeyboardButton` в новом коде
   запрещён. Сейчас соотношение 473 / 1108 — то есть большинство кнопок
   выглядят иначе, чем задумано.

2. **Экран редактируется, а не досылается.** По умолчанию —
   `edit_message_text`; `reply_text` только когда это осознанно новое событие
   (анонс в чат, результат публичной игры). Сейчас 933 / 78 в пользу
   досылки — отсюда простыни в чате.

3. **Один разделитель.** Выбери `───` (сейчас 716 против 65 у `━━`)
   и используй только его.

4. **Каждый экран строится одной функцией** вида
   `def render_<screen>(f: dict) -> tuple[str, InlineKeyboardMarkup]`.
   Текст и клавиатура рождаются вместе, а не собираются по месту.

5. **Единая навигация:** «◀️ Назад» ведёт на уровень выше, «🏠 Меню» — в корень.
   Никаких экранов-тупиков без выхода.

6. `parse_mode=ParseMode.HTML` везде — как сейчас.

7. Премиум-эмодзи (`tg-emoji`) — из общего словаря в `core/ui.py`,
   не хардкодить id по месту.

**[РЕШИ]** Если у тебя есть свой вкус по визуалу (другой разделитель, другая
структура экрана, конкретные цвета кнопок по Bot API 9.4) — впиши сюда.
Мне важнее, чтобы стиль был **один**, чем какой именно.

## 6. Главная содержательная задача: вернуть NFT в центр

Это то, ради чего всё остальное. Сейчас бот отлично умеет **узнать**, что
у игрока есть KissedFrog (46 из 91 упоминания в коде — API-обвязка See.tg,
парсинг `t.me/nft/`, каталог), и почти ничего с этим знанием не делает.

Что должно стать правдой после этого этапа:

- **Облик лягушки = конкретный гифт игрока.** Не абстрактный «Brownie
  с прибавкой», а KissedFrog #4213 с его моделью, фоном, узором.
  В коде уже есть заготовка: `[🪸 KissedFrog #{number}]({nft_url})`
- **Редкость атрибутов гифта → статус в игре.** Видимый: в профиле, в топах,
  рядом с именем в публичных событиях
- **Множитель наград включить по умолчанию** и убрать админ-тумблер
  `reward_bonus_active` — либо переосмыслить: возможно, статус должен
  давать не цифры, а видимость и косметику
- **Поднять See.tg-команды из закопанных в ядро:** `/portfolio`, `/giftcheck`,
  `/giftfloors`, `/checkgroup` — это 4 команды из 73, и они самое «на бренде»,
  что есть в проекте. Флор своего гифта в профиле, сравнение с другими холдерами
- **Без гифта играть можно**, но лягушка дефолтная. Гифт — апгрейд идентичности,
  а не платный буст

**[РЕШИ]** Тут нужен твой продуктовый выбор: NFT даёт **статус и косметику**
(моя рекомендация — люди в NFT-комьюнити платят за право выделяться)
или **игровое преимущество** (множители, доступ к контенту)? Или смесь?
Это определит весь дизайн раздела.
