# Бот-сторож для Telegram Business

Бот работает в режиме **бизнес-бота** и пишет вам в личку, когда в вашей бизнес-переписке
кто-то:

- 🗑 **удалил сообщение** — приходит его текст, автор, время и вложение (фото/голосовое/видео);
- ✏️ **изменил сообщение** — приходит «было / стало»;
- 🧨 **удалил всю переписку** — приходит сводка: сколько сообщений исчезло и что в них было.

Telegram не присылает боту содержимое удалённого сообщения — только его номер. Поэтому бот
ведёт собственный кэш входящих сообщений и вложений, и именно из этого кэша показывает,
что именно пропало.

## Быстрый старт

```bash
git clone <этот репозиторий>
cd <папка>

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # впишите BOT_TOKEN
python run.py
```

Через Docker:

```bash
cp .env.example .env      # впишите BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

Для systemd есть юнит `deploy/tg-business-watcher.service`.

## Настройка на стороне Telegram

1. **Создайте бота** у [@BotFather](https://t.me/BotFather): `/newbot`, получите токен → в `.env`.
2. **Включите бизнес-режим** (обязательно, иначе бизнес-апдейты не приходят):
   `@BotFather` → `/mybots` → ваш бот → **Bot Settings** → **Business Mode** → **Enable**.
3. **Подключите бота к аккаунту** (нужен Telegram Premium):
   Telegram → **Настройки** → **Telegram для бизнеса** → **Чат-боты** → введите @юзернейм бота.
   Там же выбирается, в каких чатах бот работает (все / кроме выбранных / только выбранные).
4. Откройте личный чат с ботом и нажмите **Start** — сюда будут приходить уведомления.

Права «отвечать от вашего имени» боту **не нужны**: для слежения хватает чтения.

## Команды

| Команда | Что делает |
|---|---|
| `/start`, `/help` | Справка и инструкция по подключению |
| `/status` | Состояние бизнес-подключения и текущие настройки |
| `/settings` | Кнопки-переключатели уведомлений |
| `/stats` | Сколько сообщений в кэше, сколько удалено и отредактировано |
| `/purge` | Полностью стереть кэш сообщений и скачанные вложения |

Переключатели в `/settings`:

- **Уведомлять об удалении** / **о правках** — включить-выключить каждый тип уведомлений;
- **Учитывать мои сообщения** — по умолчанию выключено: удаления ваших собственных сообщений
  не тревожат вас (Telegram не сообщает, кто именно удалил, поэтому чаще всего это вы сами);
- **Сохранять вложения** — скачивать медиа сразу при получении, чтобы точно показать их после
  удаления;
- **Без звука** — уведомления приходят беззвучно.

## Как это устроено

```
app/
  main.py        точка входа: конфиг, БД, диспетчер, long-polling, фоновая очистка
  config.py      чтение .env
  models.py      разбор Message: текст, тип вложения, file_id, отправитель
  db.py          SQLite: подключения, кэш сообщений, история правок, настройки
  buffer.py      склейка пачек удалений в один отчёт (удаление чата = много апдейтов)
  media.py       скачивание вложений и пересылка их владельцу после удаления
  formatters.py  тексты уведомлений (HTML)
  tracker.py     вся логика: что кэшировать, о чём и кому сообщать
  handlers/      роутеры aiogram (бизнес-апдейты и команды)
```

Отслеживаемые апдейты Bot API: `business_connection`, `business_message`,
`edited_business_message`, `deleted_business_messages`.

Несколько решений, которые стоит знать:

- **Пачки удалений.** Удаление переписки прилетает десятками апдейтов подряд. `DeletionBuffer`
  копит их `DELETE_DEBOUNCE` секунд (по умолчанию 2) и отправляет один отчёт, но не тянет
  дольше, чем `DELETE_DEBOUNCE × 5`, чтобы огромный чат не откладывал уведомление бесконечно.
- **Удаление всей переписки.** Определяется эвристикой: удалено ≥ `CHAT_DELETE_THRESHOLD`
  сообщений и в кэше чата не осталось ни одного живого.
- **Ложные «правки».** Telegram присылает `edited_business_message` и когда просто
  подгрузилось превью ссылки. Если текст и вложение не изменились — уведомления нет.
- **Вложения.** При `BACKUP_MEDIA=true` файлы до `MAX_MEDIA_MB` скачиваются сразу. После
  удаления бот сначала пробует переслать по `file_id`, затем — с диска.
- **Хранение.** Раз в 6 часов удаляются записи старше `RETENTION_DAYS` дней вместе с файлами.

## Настройки `.env`

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | Токен от @BotFather (обязательно) |
| `DB_PATH` | `data/tracker.db` | Файл SQLite |
| `MEDIA_DIR` | `data/media` | Куда складывать вложения |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс дат в уведомлениях |
| `RETENTION_DAYS` | `30` | Сколько хранить кэш (`0` — бессрочно) |
| `DELETE_DEBOUNCE` | `2.0` | Окно склейки удалений, сек |
| `CHAT_DELETE_THRESHOLD` | `5` | С какого числа удалений подозревать удаление чата |
| `PREVIEW_LIMIT` | `700` | Символов текста на сообщение в отчёте |
| `MAX_MESSAGES_IN_REPORT` | `25` | Сколько сообщений показывать в одном отчёте |
| `MAX_MEDIA_ITEMS` | `10` | Сколько вложений пересылать после удаления |
| `BACKUP_MEDIA` | `true` | Скачивать медиа заранее |
| `MAX_MEDIA_MB` | `20` | Лимит размера скачиваемого файла |
| `NOTIFY_EDITS`, `NOTIFY_DELETES`, `INCLUDE_OWN`, `SILENT_NOTIFICATIONS` | `true/true/false/false` | Стартовые значения настроек |
| `LOG_LEVEL` | `INFO` | Уровень логов |

## Ограничения Telegram (важно)

- Бизнес-функции требуют **Telegram Premium** у владельца аккаунта.
- Бот видит только сообщения, пришедшие **после** подключения: историю переписки Bot API
  не отдаёт. Сразу после подключения кэш пуст.
- Telegram **не сообщает, кто именно удалил** сообщение — только факт удаления в чате.
- Исчезающие сообщения и медиа «с одноразовым просмотром» боту недоступны.
- Секретные чаты не поддерживаются вообще.
- Уведомление приходит, пока бот подключён и запущен: если процесс лежал, Telegram отдаст
  накопленные апдейты при следующем старте (обычно в пределах суток).

## Про приватность

Бот хранит копию вашей деловой переписки на том сервере, где вы его запустили. Это ваши
данные и ваша ответственность: держите `.env`, `data/` и доступ к серверу закрытыми, ставьте
разумный `RETENTION_DAYS`, а `/purge` стирает кэш целиком. В ряде юрисдикций собеседников
нужно предупреждать о том, что переписка сохраняется — учитывайте это.
