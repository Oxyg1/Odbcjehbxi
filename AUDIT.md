## 0. Краткий диагноз

Проект не «свернул не туда» стилистически — он упёрся в **три конкретных
инженерных стены**, каждая из которых по отдельности решаема, но вместе они
делают любое изменение дорогим и страшным. Отсюда и три месяца простоя.

| Стена | Метрика | Следствие |
|---|---|---|
| Один файл, одна функция-роутер | `on_callback` = **18 840 строк**, 409 веток `if`, 1049 `return`, вложенность 8 | Любая правка кнопки требует держать в голове весь файл |
| Ошибки не видны | **818** блоков `except: … pass` из 1004 | Баг не падает, а тихо съедается. Нельзя понять, сломал ли ты что-то |
| Данные меняются гонками | Атомарный `db_coins_delta` вызван **4 раза**, а полный read-modify-write — сотни | Экономика (монеты, Stars) расходится, и это невозможно отследить из-за пункта 2 |

Вывод: **переписывать с нуля не надо.** Логика игры — самое ценное, что есть,
и она работает. Надо расшить эти три стены в описанном ниже порядке.

## 2. 🔴 Архитектура: почему проект «встал»

### 2.1 Один обработчик на все кнопки

```python
# L71912 — единственная регистрация, без pattern=
app.add_handler(CallbackQueryHandler(on_callback))
```

Все нажатия всех кнопок бота идут в одну функцию:

```
on_callback         18 840 строк   409 веток if верхнего уровня   1049 return
on_message           1 987 строк
exp_handle_callback  1 517 строк
_war_callbacks_v2    1 389 строк
_war_callbacks       1 182 строки
```

Пять функций = **21 081 строка, 29% всего проекта**.

Хуже того, специализированные роутеры вызываются **в конце** цепочки
(`handle_checkers_callback` — L50434, `exp_handle_callback` — L50656). То есть
нажатие кнопки экспедиции сначала линейно проверяет ~18 600 строк чужих условий.

### 2.2 Что с этим делать

`python-telegram-bot` умеет маршрутизировать сам — параметр `pattern=`. Это
регулярка по `callback_data`, и она превращает линейный перебор в диспетчеризацию:

```python
# было: одна функция на всё
app.add_handler(CallbackQueryHandler(on_callback))

# стало: каждый домен ловит только своё
app.add_handler(CallbackQueryHandler(exp_router,      pattern=r"^exp_"))
app.add_handler(CallbackQueryHandler(war_router,      pattern=r"^(war_|raid_|skirmish_|skd_)"))
app.add_handler(CallbackQueryHandler(casino_router,   pattern=r"^(casino_|bet_|lottery_)"))
app.add_handler(CallbackQueryHandler(checkers_router, pattern=r"^ck"))
app.add_handler(CallbackQueryHandler(battleship_router,pattern=r"^bs"))
app.add_handler(CallbackQueryHandler(freeze_router,   pattern=r"^(fz_|fzquiz_)"))
app.add_handler(CallbackQueryHandler(admin_router,    pattern=r"^(ca_|cs_|admin_)"))
# … и общий fallback последним
app.add_handler(CallbackQueryHandler(on_callback))
```

Ключевое: **это делается постепенно.** Выносишь один домен — остальные продолжают
работать через старый `on_callback`, потому что он остаётся последним в цепочке.
Никакого «большого взрыва», можно останавливаться после каждого домена.

## 3. 🔴 Деньги и данные: тихая порча

### 3.1 Пул соединений написан, но не используется

```
aiosqlite.connect(...)   — 814 вызовов
_db_pool.acquire()       —  13 вызовов
```

В докстринге `_DBPool` заявлено «10-15x ускорение при 200+ юзерах». Фактически
пул обслуживает 1.6% обращений к БД — **заявленного ускорения в проекте нет**.
814 раз на каждый чих открывается и закрывается новое соединение к SQLite.

### 3.2 Гонки на балансе

Есть правильная атомарная функция — и она почти не используется:

```python
async def db_coins_delta(uid: int, delta: int) -> int | None:
    """… защита от race condition."""   # вызвана 4 раза во всём проекте
```

Вместо неё повсеместно:

```python
f = await db_get(uid)                       # 486 вызовов
f["coins"] = f.get("coins", 0) + reward     # ~184 места
await db_save(f)                            # 327 вызовов
```

**Почему это опаснее, чем кажется.** `db_save` пишет обратно *всю строку*
целиком — все 137 колонок таблицы `frogs`:

```python
sql = f"INSERT INTO frogs ({','.join(keys)}) VALUES ({ph}) ON CONFLICT(user_id) DO UPDATE SET {upd}"
```

Значит, если игрок одновременно ловит комара и крутит казино, то обработчик,
который сохранится вторым, затрёт **не только монеты, а вообще все поля**,
записанные первым — уровень, XP, инвентарь, кулдауны. Плюс `_UserCache` с TTL
60 секунд отдаёт устаревшую копию, увеличивая окно гонки до минуты.

Это и есть механизм, которым экономика расходится без единой записи в лог.

### 3.3 Как чинить

Одно правило: **любое изменение числового поля — через SQL, а не через Python.**

```python
# ❌ read-modify-write: теряет соседние обновления
f["coins"] = f.get("coins", 0) - price
await db_save(f)

# ✅ атомарно, и сразу проверяет достаточность средств
new_balance = await db_coins_delta(uid, -price)
if new_balance is None:
    return await q.answer("Недостаточно КваКоинов", show_alert=True)
```

Начать с денежных путей: казино, дуэли, магазин, переводы, `successful_payment`.
Остальное можно мигрировать постепенно.

## 4. 🟠 Ошибки не видны

```
except Exception:   1004
    pass             818   ← 81% всех обработчиков ошибок молча глотают всё
```

Это главная причина, почему проект «страшно трогать»: **бот не сообщает о
поломках**. Упал запрос к БД, сломался парсинг, отвалился внешний API — игрок
видит зависшую кнопку, ты не видишь ничего.

Отдельно: отладочные логи оставлены на уровне ERROR (24 вызова
`logger.error("🐛 [EXP DEBUG] …")`), то есть настоящие ошибки утоплены в шуме.

**Что делать:**

```python
# ❌
except Exception:
    pass

# ✅ минимум — залогировать с контекстом
except Exception:
    logger.exception("casino_spin failed uid=%s bet=%s", uid, bet)
```

`except: pass` допустим ровно в двух случаях: удаление уже удалённого сообщения
и ответ на протухший callback. Везде остальном — `logger.exception`.
Это разовая механическая правка, но она возвращает проекту наблюдаемость.

## 8. Что важно не потерять

Отдельно стоит сказать, что сделано хорошо, потому что при рефакторинге это
легко снести:

- **Продуманная игровая экономика** — редкости, лиги, стаи, крафт, ивенты.
  Это годы дизайна, и переписывать её не нужно
- **Антифрод уже есть**: `user_risk`, `ref_fraud_suspects`, `trusted_referrers`,
  антибот-капча на комаре, заморозка подозрительных переводов, `/adminrollback`.
  Для community-бота с реальными Stars это зрелая система
- **Правильные примитивы уже написаны** — `_DBPool`, `db_coins_delta`,
  `_UserCache`. Проблема не в том, что их нет, а в том, что до них не дошли руки
  их применить. Это гораздо более выигрышная позиция, чем кажется
- **Миграции неразрушающие** (`ADD COLUMN` с проверкой) — данные игроков в порядке

Проект не в тупике. Он в состоянии, когда накопленный за год функционал
перерос выбранную в начале форму «один файл», и форму пора сменить —
не содержание.
