# Выкатка на боевого бота

Порядок один и тот же для любого обновления. Запуск сезона — отдельный шаг
в самом конце, и только после того, как бот подтверждённо живой.

## 0. Убедиться, где боевой бот

Прежде чем что-то копировать, посмотреть, откуда он реально запущен:

```bash
systemctl list-units --type=service | grep -i frog
systemctl cat frogbot | grep -E 'WorkingDirectory|ExecStart|EnvironmentFile'
```

`WorkingDirectory` — и есть каталог боевого бота (по умолчанию `/opt/frogbot`).
Каталог с исходниками, откуда идёт выкатка, должен быть **другим**. Если они
совпали — дальше не идти, иначе тестовый `.env` и тестовая база уедут в бой.

## 1. Бэкап базы

Обязательно, и не «на всякий случай», а потому что запуск сезона необратим.

Через бота: `/adminbackup` — пришлёт файл в личку.

Плюс копия на диске:

```bash
sudo -u frogbot cp /opt/frogbot/frog_game.db \
     /opt/frogbot/db_backups/before_season2_$(date +%F_%H%M).db
```

## 2. Обновить исходники

В каталоге с клоном репозитория:

```bash
git fetch origin
git checkout claude/bot-redesign-fixes-xlzvgp
git pull
git log --oneline -3        # убедиться, что пришли свежие коммиты
```

## 3. Выкатить

```bash
sudo bash deploy/install.sh
```

Скрипт идемпотентный: ставит зависимости, проверяет, что `bot.py`
компилируется, обновляет systemd-юнит и перезапускает сервис. Если файл не
компилируется — падает до перезапуска, боевой бот продолжает работать на
старом коде.

**Что скрипт НЕ трогает на сервере:** `.env`, база `*.db`, автобэкапы,
логи, сессия Telethon для `pars.py`, каталог лотов
`kissed_frog_on_sale.json`. Токен и данные игроков переживают выкатку.

## 4. Проверить, что живой

```bash
systemctl status frogbot --no-pager | head -20
journalctl -u frogbot -n 50 --no-pager
```

В логе при старте должны появиться строки про миграции и:

```
🏅 Итоги прошлых сезонов в памяти: 0
```

Ноль — это правильно, пока сезон не закрывали.

Дальше руками в боте: `/start`, открыть меню, `/season`, `/top`. Если
что-то отвечает молчанием — смотреть `journalctl`.

## 5. Запуск сезона

Только после того, как бот проверенно работает. Сначала отчёт:

```
/seasonstart
```

Он покажет, кого и что заденет, и ничего не изменит. Прочитать целиком:
сколько игроков в зачёте, кто получит облик, сколько мёртвых и сколько
в анабиозе. Затем:

```
/seasonstart ПОЕХАЛИ
```

Лучше в тихие часы: команда идёт одним массовым UPDATE, и если игрок
нажмёт кнопку ровно в этот момент, его обработчик может записать поверх
старое значение. Риск маленький, но бэкап из шага 1 — именно на этот случай.

## 6. Откат

Если после выкатки что-то не так:

```bash
cd /путь/к/клону
git checkout <предыдущий_коммит>
sudo bash deploy/install.sh
```

Старый код читает новую базу — проверено тестом `upgrade_test.py`. Но если
сезон уже запущен, откат кода **не вернёт** уровни и монеты: для этого нужна
база из шага 1.

```bash
systemctl stop frogbot
sudo -u frogbot cp /opt/frogbot/db_backups/before_season2_*.db \
     /opt/frogbot/frog_game.db
systemctl start frogbot
```

## Перед запуском сезона отдельно проверить

- **Стикер облика `Season Champ`.** Заведён с `sid: 105` — стикер должен
  стоять 105-м в паке `t.me/skinsforfroggame`, иначе у победителей сезона
  будет битая ссылка на облик.
- **Парсер лотов.** `pars.py` работает от сессии Telethon в каталоге бота.
  Выкатка её не трогает, но если каталог бота меняли — сессию придётся
  создать заново вводом кода из Telegram.
