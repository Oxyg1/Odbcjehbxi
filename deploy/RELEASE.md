# Выкатка на боевого бота

Порядок один и тот же для любого обновления. Запуск сезона — отдельный шаг
в самом конце, и только после того, как бот подтверждённо живой.

## 0. Убедиться, где боевой бот

Прежде чем что-то копировать, посмотреть, откуда он реально запущен:

```bash
systemctl list-units --type=service | grep -i frog
systemctl cat frogbot | grep -E 'WorkingDirectory|ExecStart|EnvironmentFile'
```

`WorkingDirectory` — и есть каталог боевого бота (по умолчанию `/opt/frogbot`).
Каталог с исходниками, откуда идёт выкатка, должен быть **другим**. Если они
совпали — дальше не идти, иначе тестовый `.env` и тестовая база уедут в бой.

## 1. Бэкап базы

Обязательно: запуск сезона и переход на новые экспедиции необратимы.

Через бота: `/adminbackup` — пришлёт файл в личку.

Плюс копия на диске. **Только через `.backup`, не через `cp`:** база работает
в режиме WAL, и `cp` живого файла даёт битую копию (так и случилось в августе).

```bash
sudo -u frogbot sqlite3 /opt/frogbot/frog_game.db \
     ".backup '/opt/frogbot/db_backups/before_$(date +%F_%H%M).db'"
```

## 2. Обновить исходники

В каталоге с клоном репозитория:

```bash
git fetch origin
git checkout claude/bot-redesign-fixes-xlzvgp
git pull
git log --oneline -3        # убедиться, что пришли свежие коммиты
```

## 3. Выкатить

```bash
sudo bash deploy/install.sh
```

Скрипт идемпотентный: ставит зависимости, проверяет, что `bot.py`
компилируется и запускается (`tools/test_startup.py` — настоящий `post_init`
на временной базе, Telegram заглушен), обновляет systemd-юнит и
перезапускает сервис. Если файл не компилируется или бот не взлетает —
скрипт падает до перезапуска, боевой бот продолжает работать на старом коде.

**Что скрипт НЕ трогает на сервере:** `.env`, база `*.db`, автобэкапы,
логи, сессия Telethon для `pars.py`, каталог лотов
`kissed_frog_on_sale.json`. Токен и данные игроков переживают выкатку.

## 4. Проверить, что живой

```bash
systemctl status frogbot --no-pager | head -20
journalctl -u frogbot -n 50 --no-pager
```

В логе при старте должны появиться строки про миграции и:

```
🏅 Итоги прошлых сезонов в памяти: 0
```

Ноль — это правильно, пока сезон не закрывали.

Дальше руками в боте: `/start`, открыть меню, `/season`, `/top`. Если
что-то отвечает молчанием — смотреть `journalctl`.

## 5. Запуск сезона

Только после того, как бот проверенно работает. Сначала отчёт:

```
/seasonstart
```

Он покажет, кого и что заденет, и ничего не изменит. Прочитать целиком:
сколько игроков в зачёте, кто получит облик, сколько мёртвых и сколько
в анабиозе. Затем:

```
/seasonstart ПОЕХАЛИ
```

Лучше в тихие часы: команда идёт одним массовым UPDATE, и если игрок
нажмёт кнопку ровно в этот момент, его обработчик может записать поверх
старое значение. Риск маленький, но бэкап из шага 1 — именно на этот случай.

## 6. Откат

Если после выкатки что-то не так:

```bash
cd /путь/к/клону
git checkout <предыдущий_коммит>
sudo bash deploy/install.sh
```

Старый код читает новую базу — проверено тестом `upgrade_test.py`. Но если
сезон уже запущен, откат кода **не вернёт** уровни и монеты: для этого нужна
база из шага 1.

```bash
systemctl stop frogbot
sudo -u frogbot cp /opt/frogbot/db_backups/before_<дата>.db /opt/frogbot/frog_game.db
sudo rm -f /opt/frogbot/frog_game.db-wal /opt/frogbot/frog_game.db-shm
systemctl start frogbot
```

Здесь `cp` можно: бот остановлен, копируется файл бэкапа, а не живая база.
Старые `-wal`/`-shm` удалить обязательно, иначе SQLite наложит их на
восстановленную базу.

## Перед запуском сезона отдельно проверить

- **Стикер облика `Season Champ`.** Заведён с `sid: 105` — стикер должен
  стоять 105-м в паке `t.me/skinsforfroggame`, иначе у победителей сезона
  будет битая ссылка на облик.
- **Парсер лотов.** `pars.py` работает от сессии Telethon в каталоге бота.
  Выкатка её не трогает, но если каталог бота меняли — сессию придётся
  создать заново вводом кода из Telegram.

## Новые экспедиции: первая выкатка

Включаются сразу, отдельной команды нет. При первом старте бот один раз
(отметка `mig_ex2_switch` в настройках):

- закрывает старые экспедиции и сборы, которые шли в момент выкатки, и
  возвращает участникам взятые монеты; вступившим — ещё и припасы монетами
  (у создателя сбора старый код их не списывал), лягушки разблокируются;
- обменивает припасы старого магазина в инвентаре на монеты по цене покупки
  (еда 30, зелье 60, факел 50, амулет 100);
- пишет затронутым игрокам и присылает сводку в админ-чат.

Старые таблицы `expeditions` и `expedition_members` остаются для истории.

После выкатки:

1. **Стикеры обликов.** `Reed Rambler`, `Fog Wader`, `Flour Hopper` заведены
   с `sid` 106, 107, 108 — стикеры должны стоять 106–108-м в паке
   `t.me/skinsforfroggame`, иначе у собравших набор будет битая ссылка.
2. **`/adminexp`** — идущие экспедиции, сводка за неделю, ошибки в маршрутах
   (если есть). Кнопка «💸 Старые ставки» — вернуть монеты, которые выжившие
   брали в старые экспедиции и не получили обратно. Возврат за этот сезон
   или за всё время — решать тебе, сделать его можно один раз.
3. **Пройти маршрут самому** — `/expedition` или площадь → «Экспедиция».

### Если правишь тексты маршрутов

Тексты и цифры — в `exp_routes.py`, правила письма в шапке файла. После
правки:

```bash
python3 tools/test_expeditions.py      # должно кончиться «ВСЁ ОК»
```

Тест проверяет данные маршрутов, ширину строк и прогоняет экспедиции на
временной базе — боевую не трогает. Ключи стоянок (`"key"`) лучше не
переименовывать, пока кто-то в пути: экспедиция переживёт, но покажет
заглушку вместо стоянки.

## Статистика: после выкатки

Включается сама. Таблицы `st_active`, `st_use`, `st_cnt`, `st_daily`
создаются при старте; данные копятся с первого сброса — через 5 минут.

- **Сразу видно** всё, что лежит в своих таблицах: игроки, новые по дням,
  удержание по неделям (по `last_seen`), облики, экспедиции, доходы по
  старому счётчику продаж.
- **С выкатки** начинают копиться заходы по дням, функции, потоки монет,
  смерти, блокировки и ошибки. Через сутки появится D1, через неделю —
  отток и полная «неделя» в сводке, через месяц — «липкость» за 30 дней.

Где смотреть: админка → «📊 Статистика» или `/adminstats`. Разобрать
целиком: «📄 Отчёт файлом» или `/adminreport 60` (по дням — за 60 дней).

Тест — `python3 tools/test_stats.py`, должно кончиться «ВСЁ ОК».

## Полоски статов из премиум-эмодзи

После выкатки один раз, в личке с ботом:

```
/adminbars
```

Бот сам создаст пак `frogbars_by_<имя бота>` из 144 кусочков (минуты две,
сообщение показывает ход) и включит полоски в карточке лягушки. Если
Telegram оборвёт загрузку — повторить команду, продолжит с того же места.

- выключить и вернуть обычные █░: `/adminbars выкл`, включить: `/adminbars вкл`;
- после новой нарезки (`python3 tools/make_bars.py` и коммит картинок):
  `/adminbars заново`.

Тест — `python3 tools/test_bars.py`, должно кончиться «ВСЁ ОК».
